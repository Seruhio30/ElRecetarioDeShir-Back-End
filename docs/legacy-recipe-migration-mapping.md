### Type ambiguities intentionally resolved

- `Causa Limeña -> MAIN_COURSE`: often served as an appetizer, but no appetizer type exists.
- `Papa a la Huancaína -> SIDE_DISH`: can be appetizer or accompaniment; `SIDE_DISH` is the closest available type.
- `Guacamole -> SAUCE`: technically a dip/accompaniment; `SAUCE` is the closest available type.
- `Totopos -> SIDE_DISH`: snack/accompaniment; no snack type exists.
- `Enyucado de Carne -> MAIN_COURSE`: can be served as snack/appetizer, but its filled preparation is best represented as a main course with the current enum.
- `Sopa Azteca -> MAIN_COURSE`: no soup type exists.
- `Puré de Papa -> SIDE_DISH`: although it may be used as a base, its primary role is accompaniment.

## Future import strategy

Use a dedicated Java legacy importer executed through an explicit Spring Boot import profile.

Do not use a Flyway data migration.
Do not use a permanently active `CommandLineRunner`.
Do not use an external ad-hoc SQL script.

Recommended shape for `feat/legacy-recipe-import`:

1. Add the frozen legacy source/mapping as an importer resource.
2. Implement a dedicated importer service using the existing domain model and `RecipeRepository`.
3. Expose execution only through an `ApplicationRunner` enabled by a dedicated profile/property such as `legacy-import`.
4. Run a complete preflight before writing:
   - source count must equal 26;
   - all mappings must resolve;
   - all slugs must be unique;
   - all ingredient and step arrays must be non-empty.
5. Import in one transaction where practical.
6. Use slug as the stable identity for duplicate prevention.
7. Import behavior:
   - if none of the 26 slugs exist, perform the import;
   - if all 26 already exist and match expected imported identity, finish successfully as a no-op;
   - if only a subset exists or a slug conflicts, abort before importing the remainder.
8. After persistence verify:
   - 26 source recipes;
   - 26 expected slugs present;
   - expected ingredient count for every recipe;
   - expected step count for every recipe;
   - exactly one expected image metadata row per recipe once image persistence is enabled.
9. Produce a concise import result and exit.
10. Never enable the importer during normal application startup.

Why this strategy:

- uses the real Java domain model and enum validation;
- respects aggregate relationships and lifecycle callbacks;
- is testable before touching production data;
- supports controlled and idempotent reruns;
- keeps application seed/import data out of Flyway schema history;
- avoids an always-active startup importer;
- avoids duplicating domain rules in SQL or an external script.
